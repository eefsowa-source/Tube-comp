# UAD/Brainworx 레퍼런스 아날로그 회로 — 난이도 평가와 효율적 개발 계획

이 문서의 이전 버전은 단계 목록과 코드 스케치 중심이었고, CPU 비용과
검증 수단의 제약을 반영하지 못했습니다. 이 버전은 현재 체크아웃에서 직접
측정한 수치를 근거로 난이도를 다시 매기고, 실패 비용이 낮은 순서로
재배열합니다.

---

## 1. 측정된 현재 상태

체크아웃: `main` (`dbc78f8`) + 미커밋 변경. 신규 DSP/검증/측정 도구 포함.

이미 구현되어 있는 것:

- 12AX7 트라이오드의 Norman Koren 정적 모델 (`KorenTriode.h`)
- 플레이트 회로를 실제 WDF 1포트 루트로 두고 뉴턴-랩슨으로 푸는 구조
  (`TriodeStage.cpp`)
- 캐소드 사그(Rk||Ck 시정수)에 의한 프로그램 의존적 자기 바이어스
- 입력/출력 커플링의 1차 하이패스, 틸트 필터
- ADAA 웨이브셰이퍼 경로, 1x/2x/4x/8x 오버샘플링

Stage 1 이후 비용 측정 (48 kHz, 512 샘플 블록, 스테레오 1 인스턴스, 실시간 대비 %):

| 설정 | 1x | 2x | 4x | 8x |
|---|---|---|---|---|
| WDF 트라이오드 | 2.3 | 5.1 | 9.9 | 18.8~19.7 |
| Fast 웨이브셰이퍼 | 0.21 | 0.49 | 1.0 | 2.0 |

4회 반복 측정값입니다. 첫 실행에서 8x가 46.8%로 나온 적이 있으나 이후
18.8~19.7%로 안정되어, 그 값은 머신 경합으로 판단합니다. 오버샘플 배수에
거의 선형으로 증가하므로 비용의 지배 항은 오버샘플러 필터가 아니라
트라이오드 스테이지 자체입니다.

시동 비용: Stage 1에서 4개 품질 스테이지의 무음 워밍업을 제거하고 동작점을
해석적으로 초기화했습니다. `prepareToPlay` 직접 계측은 약 84~97 ms에서
0.2 ms로 줄었고, 첫 오디오 블록의 잔여 트랜지언트도 제거됐습니다.

검증 자산: CTest 9개 통과, auval 통과, pluginval strictness 10 VST3/AU 통과,
`Tools/sound_baseline.cpp` (THD/H2/H3, 비정합 프로브 앨리어싱, 처리 비용,
컴프레서 정적 커브, 두 모델 레벨 매칭).

## 2. 난이도

| 항목 | 구현 난이도 | 검증 난이도 | CPU 영향 | 판단 |
|---|---|---|---|---|
| 뉴턴 솔버 정리 (해석적 미분) | 중간 | 낮음 (널 테스트) | 약 -16% | 완료 (Stage 1) |
| 워밍업 제거 (DC 동작점 정확 해) | 낮음 | 낮음 | 시동 -85 ms | 완료 (Stage 1) |
| 피드백 Vari-Mu 토폴로지 | 중간~높음 | 높음 (청취) | 거의 없음 | 코드 완료, 청취 대기 |
| 2단 트라이오드 | 중간 | 중간 | 스테이지당 +100% | 비용 통제 전제 |
| 트랜스포머 (비선형 인덕터) | 높음 | 중간 | +50~100% | 프로토타입 후 결정 |
| Koren 파라미터 세트화 | 낮음 | 높음 (측정 데이터 없음) | 없음 | 조건부 |
| 전원 sag/리플 | 낮음 | 낮음 | 미미 | 후순위 |
| TMT (채널 공차) | 낮음 | 낮음 | 약간 | 후순위 |

진짜 어려운 지점은 회로 수학이 아닙니다. 세 가지입니다.

첫째, CPU 헤드룸. 현재 단일 스테이지가 8x에서 약 19%입니다. 여기에 스테이지를
하나 더 얹으면 약 45%가 되어 단일 인스턴스로도 실사용이 어렵습니다. 회로를
더하기 전에 기존 스테이지의 비용을 줄여야 합니다.

둘째, 레퍼런스 부재. 저장소에 실제 하드웨어 측정 곡선도, 레퍼런스 녹음도
없습니다. 데이터시트 피팅은 약한 증거이고, 널 테스트는 "내 모델과 내 모델이
같다"는 것만 증명합니다. UAD/Brainworx의 내부 구현은 공개되어 있지 않으며,
공개된 것은 마케팅 수준의 설명입니다. 따라서 "UAD급" 주장은 현재 검증
불가이며, 계획은 이 주장을 목표로 삼지 않습니다.

셋째, 피드백 루프 설계. 검출을 출력에서 유도하면 루프 이득과 위상에 따라
발진할 수 있고, 기존 룩어헤드와 지연 보상(PDC) 구조와도 상호작용합니다.
코드량은 적지만 안정성 확인과 청취 판단이 필요합니다.

## 3. 효율적 개발 순서

각 단계는 게이트로 끝냅니다. 게이트를 통과하지 못하면 다음 단계로 넘어가지
않습니다. 이 순서의 목적은 되돌리기 쉬운 것부터 처리해서, 비싼 실패를
나중으로 미루는 것입니다.

### Stage 0 — 기준 고정 (0.5일)

목표 동작을 수치로 먼저 정의합니다. 예를 들어 "드럼 버스에서 6 dB 감쇠일 때
어택/릴리즈 포락선", "보컬에서 프로그램 의존성의 정도". 하네스를 정적 톤에서
동적으로 확장합니다: 스텝 응답, GR 대 입력 레벨 곡선, attack/release 시정수
피팅. 현재 빌드의 수치를 기준 스냅샷으로 저장합니다.

게이트: 이후 모든 변경을 이 스냅샷과 비교할 수 있는 상태.

### Stage 1 — CPU와 시동 비용 정리 (0.5~1일)

여기가 효율의 핵심입니다. `TriodeStage.cpp`의 뉴턴 솔버는 반복마다
`korenPlateCurrent`를 3회 호출합니다. 중앙차분으로 도함수를 구하기
때문입니다. 이 루프는 최대 12회 반복하고 허용오차가 1e-6이라, 샘플당
최대 36회의 초월함수 평가가 발생합니다.

Koren 모델의 도함수는 닫힌 형태로 나옵니다. s = 1/mu + Vgk/sqrt(Kvb+Vpk^2),
u = 1/(1+exp(-Kp*s)), L = ln(1+exp(Kp*s))로 두면

    E1      = (Vpk/Kp) * L
    dE1/dVpk = L/Kp + Vpk*u*ds/dVpk
    ds/dVpk  = -Vgk*Vpk*(Kvb+Vpk^2)^(-3/2)
    dIp/dVpk = (Ex/Kg1) * E1^(Ex-1) * dE1/dVpk

즉 함수 1회 평가로 값과 도함수를 함께 얻습니다. 반복당 평가가 3회에서 1회로
줄어듭니다. 당초 반복 횟수 감소까지 기대해 3배 이상을 예상했지만, 실행 결과
아래와 같이 16%에 그쳤습니다. 그 이유도 함께 기록합니다.

같이 처리할 것: 시드가 정확하면 0.25초 워밍업이 불필요합니다. 실제로 시드는
정확하지 않았습니다. 고정점 반복의 루프 이득이 gm*Rk로 약 3이라 발산했고,
그래서 시드가 실제 동작점에서 약 17 V 벗어나 있었습니다. 뉴턴법 대신 감쇠
고정점(완화 계수 0.25)으로 바꿔 동작점을 정확히 풀면 워밍업이 필요 없어집니다.

게이트(실행 결과):

- 도함수 정확도: 수치 미분(리처드슨 외삽) 대비 상대오차 3.9e-10, 2010개
  도통점. 회귀 테스트 `Tests/KorenSlopeTest.cpp`로 고정.
- 널 테스트: 오디오 구간 최대 -115.7 dBFS, RMS -143.9 dB(신호 대비), 파일
  마지막 0.5초는 비트 동일. 오디오는 사실상 무변화.
- 시작 구간: 기존 워밍업이 남기던 4.5e-05의 잔여가 사라져 리드인 무음이
  -86 dBFS 차이(신규 빌드가 더 깨끗함), `ProcessorTest`의 시작 트랜지언트
  단언은 4.5e-05에서 정확히 0으로 개선.
- 준비 시간: 84~97 ms에서 0.2 ms로 감소(`null_render`가 직접 계측).
- 비용: wdf-8x 22.5%에서 18.8~19.7%로 감소. wdf-1x 2.7→2.3, wdf-4x
  11.5→9.9. 목표였던 10% 이하는 미달.

미달 원인(측정으로 확인): 솔버 반복 횟수는 중앙차분과 해석적 미분이 평균
3.085회로 동일했습니다. 즉 샘플당 Koren 평가는 10.3회에서 4.1회로 2.5배
줄었지만 비용은 16%만 줄었습니다. Koren 평가가 샘플당 비용의 일부에 불과하고,
나머지는 뉴턴 루프 자체와 상태 갱신(커플링·캐소드·클램프)입니다. 따라서
8x에서 10% 이하를 얻으려면 함수 단위 미세 최적화가 아니라 알고리즘 변경이
필요합니다(예: 트라이오드만 낮은 배수로 처리하는 혼합 레이트, 또는 표 기반
평가).

### Stage 2 — 피드백 Vari-Mu 토폴로지 (구현 완료, 청취 게이트 대기)

새 DSP 블록을 만들지 않고 컨트롤 경로만 바꿨습니다. `Detector Mode` 파라미터로
Feedforward/Feedback을 선택할 수 있고, 기본값과 모든 factory preset은
Feedback입니다. Feedback에서는 한 샘플 지연된 실제 압축 출력이 기존
사이드체인 HPF→정류→attack/release 경로로 되먹임됩니다. 한 샘플의 인과성으로
동일 샘플의 암시적 대수 루프와 발진 위험을 피하면서 블록 경계를 넘는 상태를
유지합니다.

기존 부품을 재사용합니다: 사이드체인 하이패스, 정류기, attack/release 시정수.
비용은 거의 변하지 않습니다.

위험: 루프 이득/위상에 의한 발진, 룩어헤드와 PDC 구조와의 상호작용,
그리고 무엇보다 "느낌"이 달라지는 것이 개선인지 아닌지에 대한 판단.

현재 코드 게이트 결과:

- 새 `CompressorFeedbackTest`: Feedforward 12.53 dB GR, Feedback 7.18 dB GR
  (0.9 peak, -18 dB threshold, 4:1), 2 dB 이상 차이 단언 통과.
- 3초 stereo stress 입력(20:1, 0.1 ms attack, 5 ms look-ahead)에서
  NaN/Inf, 2.0 초과 출력, GR 범위 이탈 없음.
- 전체 CTest 9/9 통과.
- 1 kHz 정적 곡선에서 0 dBFS 입력: Feedforward 12.30 dB GR /
  -9.94 dBFS RMS, Feedback 7.12 dB GR / -4.85 dBFS RMS.

남은 게이트: Feedforward 대비 Feedback의 레벨 매칭 블라인드 청취. 코드 테스트와
정적 곡선은 안정성과 동작 차이를 증명하지만 "더 좋다"는 청취 결론을 대신하지
않습니다.

  측정 tone transfer는 Feedforward `+3.404 dB`, Feedback `+6.522 dB`로 기존과
  일치했고, float 출력 peak가 각각 `+3.717/+6.085 dBFS`인 점은 현재 모델 매칭
  게인 정책의 관찰 사항으로 남긴다. 이는 이번 수정에서 임의 리미터를 추가하지 않은
  이유이며, 최종 헤드룸 결정은 별도 제품 사양/청취 게이트다.
- 설치 후 현재 화면 점검에서도 REAPER의 FX 체인에 `VST3: EON-Vari mu DSP (EON)`이
  로드되고 `Feedback`으로 표시되며, Ableton의 `qa-stage2-ableton-recall`에는
  `Detector Mode` 자동화 레인과 `Feedback` 값이 표시되었다. 다만 두 DAW 프로세스가
  새 바이너리 설치 전에 이미 실행 중이었으므로 이 점검은 UI/프로젝트 상태 증거이며,
  새 SHA256에 대한 DAW 로드 증거로 승격하지 않는다. 정확한 해시 바인딩은 DAW를
  재시작하거나 인스턴스를 완전히 언로드한 뒤 동일 QA 프로젝트를 다시 열어야 한다.

### PuigChild 670 계열 동작 레퍼런스 알고리즘 패스(2026-09-22)

공개된 PuigChild 동작 설명을 기준으로, 기존 Custom 모드를 보존하면서
Fairchild 계열의 시간상수와 스테레오 검출 동작을 선택할 수 있게 했다. Waves 공개
매뉴얼은 660/670을 튜브 기반 variable-mu limiter로 설명하고, 변압기 롤오프,
긴 release, 670의 독립적인 양 채널 경로를 공개한다. 이 패스는 그 공개 동작을
제품 수준의 방향성으로 사용한 것이며 Waves의 비공개 회로/코드나 상용 제품과의
동일성을 주장하지 않는다.

- `Time Constant`: `Custom`, `1`~`6`을 추가했다. 1~4는 공개된 attack/release
  범위를 사용하고, 5~6은 프로그램 의존 release 상태를 사용한다. 5~6의
  auto-release는 공개 시간상수의 동작 범위를 안정적으로 재현하기 위한 근사이며,
  Waves 내부 구현의 복제는 아니다.
- `Link`: `Left/Right`, `Linked`, `Lat/Ver`를 추가했다. `Lat/Ver`는 실제 stereo
  인스턴스에서만 M/S 검출을 사용하고, mono에서는 linked 검출로 안전하게 fallback한다.
- 기존 Feedforward/Feedback detector, look-ahead, sidechain HPF, WDF/ADAA 경로와
  파라미터 ID 순서는 유지했다. 새 파라미터는 state 호환을 위해 끝에 추가했다.
- DSP 프로그램 테스트에서 100 ms 후 release가 TC1 `6.76 dB`, TC4 `9.27 dB`로
  분리되었고, link 모드 렌더는 L/R `0.10398`, Linked `0.06095`, Lat/Ver
  `0.04127`의 유한 출력으로 확인됐다.
- Release CTest는 9/9, `pluginval` strictness 10은 `SUCCESS`, `auval`은
  `AU VALIDATION SUCCEEDED`를 기록했다. 설치 바이너리 SHA256은 VST3
  `5d01a3ec05da46c5966e14ec6f341b4f654d10070ceb761c8a784b5e3fb5bef2`, AU
  `e5ce8d93deeebace06f2e4131ce8ff6cb68729f62407a3de42c505cba5ea1a4c`이다.
- REAPER를 제외하고 EON `eonqc`/`eonqc-host` 경로로 48 kHz, 512 samples,
  stereo 5개 시나리오를 다시 실행했다. `smoke_silence`, Feedforward, Feedback,
  TC6, Lat/Ver가 모두 `passed: true`였고 non-finite는 0, 좌우 peak 편차는 0 dB였다.
  실행 ID는 `f590dd7ee68ca5ecb6121e3531f24b7f5d793097b336b24b85cf79dad5378bc3`,
  VST3 해시는 위 `5d01a3...bef2`, EON host SHA256은
  `232a1a0ca093c9ed13365fe1e9db0de91003d9d6a2774fe32254e338a6eb9f8a`이다.

다음 품질 게이트는 동일한 SHA256의 REAPER와 Ableton Live 인스턴스를 완전히
언로드/재로드한 뒤, 48 kHz와 실제 프로젝트 버퍼에서 자동화·청취를 확인하는
   것이다. 현재 결과는 코드/CTest/pluginval/AU/렌더 호스트 증거이며, 실제
   하드웨어 또는 PuigChild와의 귀/측정 일치 증거는 아니다.

### Stage 3 — 2단 증폭 (2~3일, Stage 1 통과 후에만)

Stage 1의 헤드룸은 예상보다 작았습니다(16% 감소). 2단을 8x에서 그대로
쌓으면 약 37%가 되어 여전히 실사용이 어렵습니다. 따라서 이 단계는 혼합

게이트: 비용 상한 초과 시 스테이지 수를 줄이거나 Stage 2 상태로 유지.

### Stage 4 — 트랜스포머 (2~3일, 채택 불확실)

먼저 오프라인 프로토타입으로 스펙트럼과 THD 변화를 측정합니다. 비용과

요구하므로 Stage 1의 정리가 선행 조건입니다.

게이트: 측정 가능한 스펙트럼 차이, 비용 상한, 청취.

### Stage 5 — 후순위 (1~2일)

전원 sag/리플과 TMT. 측정으로 이득이 확인될 때만 착수합니다.

## 4. 하지 말아야 할 것

레퍼런스 하드웨어나 측정 데이터 없이 "UAD/Brainworx 수준"을 주장하는 작업.

소비합니다.

CPU 정리 없이 스테이지를 추가하는 것. 2단 8x는 단일 인스턴스에서 약 37%가
되어 실사용이 어렵습니다.

## 5. 검증 전략과 한계

## 8. 사운드 + UI/UX 통합 업그레이드 계획 (2026-09-29)

UAD/Brainworx 등급을 목표로 한 통합 계획입니다. 기준은 현재 체크아웃의 코드를
직접 읽고, 기존 측정값(8x WDF ≈ 실시간의 19%, CTest 9/9, pluginval/auval
통과)을 근거로 합니다. "UAD급" 자체는 검증 불가능한 주장이므로 유지하지
않고, 측정 가능한 항목별 목표만 세웁니다.

### 8.1 갭 분석 (코드 기준, 측정/관찰 사실만)

사운드:

- 게인 감소가 청정 gain computer입니다. `Compressor::process`는 지연선에서
  나온 신호에 dB 게인을 곱할 뿐, GR이 튜브 스테이지의 동작점에 영향을 주지
  않습니다. Fairchild 계열의 핵심은 GR이 remote-cutoff 튜브의 바이어스/gm을
  변조해 왜곡 양 자체가 프로그램 의존적이라는 점입니다. 현재는 컴프레서와
  트라이오드가 직렬로만 붙어 있어 이 상호작용이 없습니다. 이것이 청감상
  가장 큰 갭입니다.
- 트랜스포머가 없습니다. 입력/출력 트랜스포머의 저역 포화와 고역 롤오프는
  UAD Fairchild 설명에서 음색의 큰 부분으로 언급됩니다.
- 채널 공차(TMT)와 전원 sag/리플이 없습니다.
- CPU 예산이 없습니다. 단일 스테이지 8x가 약 19%라 회로를 더 얹을 여지가
  없습니다. Stage 1의 해석적 미분 정리로 16%만 줄어 함수 미세 최적화로는
  부족하다는 것이 이미 확인되었습니다.

UI/UX:

- 상용 등급 툴바가 없습니다. 프리셋 이름 표시와 이전/다음, A/B 비교,
  undo/redo, UI 크기 선택이 모두 없습니다.
- 노브 값은 드래그 중에만 표시됩니다(`drawRotarySlider`의
  `isMouseButtonDown` 분기). UAD 계열은 상시 readout 또는 마우스오버
  readout을 제공합니다.
- VU 3개는 모드 전환(입력/출력/GR)과 0VU 캘리브레이션이 없고, GR 미터는
  0~24 dB를 선형으로 매핑합니다.
- Attack/Release가 ms 노브와 Time Constant 콤보박스로 이중 노출되어
  TC 1~6 선택 시 ms 노브가 무의미해지는 모순이 있습니다.
- Oversampling이 자동화 파라미터로 노출되어 레이턴시가 자동화 중
  바뀝니다. DAW에 따라 PDC 재계산이 문제가 될 수 있습니다.
- 워크트리에 melatonin_inspector(Debug 전용) 연동이 미커밋 상태로
  있습니다. 개발 도구로 커밋 가치가 있습니다.

### 8.2 Track S — 사운드

| ID | 항목 | 구현 난이도 | CPU 영향 | 비고 |
|---|---|---|---|---|
| S1 | CPU 재확보 | 중간~높음 | 8x 19.0%→11.9% (완료, §8.8) | S3/S4의 전제조건 |
| S2 | Vari-mu GR→바이어스 커플링 | 중간 | +5% 이내 | 최고 청감 가치 |
| S3 | 트랜스포머 (선형 근사 우선) | 낮음(선형)/높음(비선형 WDF) | 선형 +0.3~1.0 pp, 비선형 +50% 이상 | 선형 완료(§8.9), 청취 대기 |
| S4 | TMT 채널 공차 | 낮음 | 미미 | Brainworx 특성 |
| S5 | 전원 sag/리플 | 낮음 | 미미 | S2 이후 평가 |

S1 — CPU 재확보. 세 가지를 순서대로 실험합니다.

  a. 뉴턴 허용오차 완화(1e-6→1e-5)와 최대 반복 단축. 코드 변경이 거의
     없어 가장 먼저 시도합니다. 널 테스트로 출력 차이를 -100 dBFS 이하로
     요구합니다.
  b. Koren 평가의 2D LUT+보간. Ip(Vgk, Vpk)가 두 변수라 테이블 크기와
     정확도의 균형을 sound_baseline의 THD/H2/H3 측정으로 검증합니다.
  c. 혼합 레이트: 트라이오드 스테이지만 4x에 두고 나머지 경로를 8x에
     두는 분리 오버샘플링. 구조 변경이 크므로 a+b가 부족할 때만.

  게이트: 8x 비용 ≤12%, THD/H2/H3 변화 ≤0.05 dB, 앨리어싱 마진 유지,
  CTest 9/9.

S2 — Vari-mu GR→바이어스 커플링. 실제 회로에서 제어 전압은 튜브의
그리드 바이어스를 끌어내려 gm을 줄입니다. 구현 방향:

- `Compressor`에 채널별 GR 버퍼 노출(control-rate, 현재 atomic은 max
  하나뿐이라 채널별 경로 추가가 필요).
- `PluginProcessor`가 블록의 GR 엔벨로프를 `TriodeStage`에 전달하고,
  오버샘플 도메인에서 홀드 또는 선형 보간으로 per-sample 적용.
- GR → Vk 오프셋 또는 grid DC bias 변조로 매핑. 매핑 기울기는
  sound_baseline으로 캘리브레이션: GR 0/6/12 dB에서 H2와 THD 증가량을
  측정해 목표 방향을 정합니다.
- Feedback 토폴로지와의 상호작용 주의: feedback 검출은 현재 컴프레서
  출력(새추레이션 전)입니다. GR→바이어스를 넣으면 실제 하드웨어처럼
  새추레이션 출력이 검출로 돌아가는 구조가 더 정직하므로, feedback 모드의
  검출 소스를 최종 출력으로 옮기는 변경을 같은 단계에서 검토합니다.

게이트: CTest + 안정성 스트레스, GR↑ 시 THD/H2 증가량 측정 가능,
eonqc 5 시나리오(REAPER 제외), CPU +5% 이내, 레벨 매칭 블라인드 청취.

S3 — 트랜스포머. 먼저 선형 근사(저역 1차 벌어짐 + 고역 롤오프 + 아주
약한 tanh)를 "Transformer" 토글로 넣고 스펙트럼을 측정합니다. 청감
이득이 확인되면 비선형 인덕터 WDF를 오프라인 프로토타입으로 만든 뒤
통합 여부를 결정합니다. 비선형 버전은 뉴턴 솔버를 하나 더 요구하므로
S1 통과가 전제입니다.

S4 — TMT. Rk, Rp, Koren 파라미터에 ±0.5~1%의 결정론적 채널 분산과
강도 파라미터를 추가합니다. 구현은 쉽지만 L/R 위상·레벨 상관의
측정 가능한 차이와 청취 게이트가 필요합니다.

S5 — 전원 sag/리플. GR 연동 B+ 드룹으로 2차 프로그램 의존성을 만듭니다.
S2 결과가 좋으면 그 연장선으로 평가하고, 아니면 보류합니다.

### 8.3 Track U — UI/UX

(Input→Threshold/DC→TC→Output)으로 정렬합니다. 좌우 미터 배치의
센터패널형 전면 재설계는 선택 사항으로 둡니다.

1. U0 + U1 + U3 + U4 (저위험, 즉시 착수 가능)

### 8.6 호스트 스모크 게이트 (2026-09-29, U2 기준)

U2(미터 업그레이드)가 반영된 설치 VST3(`a454dc3e…`)를 EON
`soundcraft`/`eonqc-host`(host 0.5.0; JUCE v9.0.1, host SHA `e9c368a8…`)
경로로 48 kHz, 512 frames, stereo, effect(2 in/2 out)에서 렌더했다. U2는
미터링만 바꾸고 오디오 경로는 건드리지 않았다. 증거는
`docs/evidence/eon-vari-u2-20260929/`에 보존한다.

- 결과: 6/6 통과 — `smoke_silence`(플로어) + nominal -18 dBFS 4개
  (FF / FB / TC1 / Lat·Ver) + hot -12 dBFS 1개. 전 시나리오
  `channel_peak_delta_db = 0.000`, `non_finite = 0`, `realtime_factor ≈ 7x`.
- 계약: `soundcraft 0.2.0`(git `ee5f9ae`), measurement algorithm `0.3.0`,
  manifest SHA `ba1361cf…`, contract/run_id `336be71c…`.
- 기존 `build/stage2-soundcraft.json`은 리퍼 시절의 -6 dBFS 레벨을 그대로 써서
  host 0.5.0의 `|x| <= 1.0` 게이트를 통과하지 못했다. 스테이징을 형제
  플러그인(EE-1073, EON 1073/737 GOD) 관례인 -18/-12 dBFS로 맞췄다.

헤드룸 관찰(측정, 회귀 아님): drive 6 dB(기본)·output 0 dB에서 출력은
대략 -12 dBFS 입력을 넘으면 0 dBFS를 초과한다. -18 dBFS → -6.5 dBFS,
-12 dBFS → -1.1 dBFS, -9 dBFS → 첫 위반 샘플 -1.05(약 +0.45 dBFS). 같은
-6 dBFS 입력에서 drive 0 dB이면 -2.6 dBFS, output -12 dB이면 -8.3 dBFS였다.
drive 스테이지가 게인을 더하고 Output이 makeup/트림을 담당하기 때문이며,
U2 이전 바이너리(리뷰 런 SHA `07c77b80`, -6 dBFS에서 peak 1.534)에도
동일하게 존재했다. 핫 입력에서 사용자가 Output을 내리는 정상 동작으로 보고,
S2 착수 시 게인 스테이징을 다시 확인한다.

### 8.7 S2 구현 — GR → 튜브 바이어스 커플링 (2026-09-30)

구현 완료, 코드·호스트 게이트 통과. 청취 게이트만 대기합니다. 증거는
`docs/evidence/eon-vari-s2-20260930/`에 보존합니다.

설계:

- `Compressor`가 블록별 GR 피크를 노출합니다(`getBlockGainReductionDb`).
  블록 끝값이 아니라 피크를 쓰므로 블록 첫 샘플만 스치는 트랜지언트도 놓치지
  않습니다.
- `PluginProcessor`가 그 GR로 `TriodeStage`에 제어 전압을 겁니다:
  `controlBias = -0.15 V/dB × GR`, 최대 -1.8 V. 그리드 DC 오프셋은 입력
  커플링 하이패스(Cin) *뒤* 튜브 방정식 안에 주입하므로 하이패스에 지워지지
  않고 동작점을 실제로 이동시킵니다.
- 이중 계상 방지: 바이어스가 낮추는 소신호 이득을 같은 스테이지에서
  보상합니다(`1.36·δ + 0.63·δ²` dB, 실측 피팅). 레벨 법칙은 컴프레서가
  단독으로 소유하고, 커플링은 고조파 성격만 바꿉니다.
- 안정성: 제어 전압과 보상 이득을 오버샘플 도메인에서 12 ms 원폴로 평활합니다.
  이 시간 상수는 GR 엔벨로프를 따라가면서도 동작점 이동을 출력 커플링
  네트워크보다 느리게 만들어, 트랜지언트에서 DC 플레이트 전압이 튀어 생기는
  썸프를 막습니다(임펄스 프리링잉 1.2e-3 → 1.8e-4).
- Fast(웨이브셰이퍼) 모델에는 바이어스가 없으므로 커플링이 적용되지 않습니다.

측정:

- ProcessorTest 케이스 10: 바이어스 0 → -1.8 V에서 H2 -18.5 → -10.2 dBc
  (+8.3 dB), 전 구간 출력 레벨 오차 ≤ 0.05 dB.
- ProcessorTest 케이스 11: GR 0이면 바이어스 0, GR이 커지면 더 차갑게(엔드투엔드).
- eonqc 6/6 통과, hot(-12 dBFS) 시나리오 H2 -29.8 → -27.0 dBc(+2.9 dB),
  전 시나리오 RMS 변화 ≤ 0.17 dB.

한계와 다음 단계:

- 커플링 깊이(0.15 V/dB)와 상한(-1.8 V)은 아직 청취로 검증하지 않았습니다.
  상수 두 개로 조절 가능하니 레벨 매칭 블라인드 청취 후 확정합니다.
- 피드백 검출 소스를 최종 출력으로 옮기는 변경(§8.2)은 이번에 하지 않았습니다.
  현재 feedback 검출은 컴프레서 출력(새추레이션 전) 그대로입니다.
- CPU: eonqc `realtime_factor` 7.0x → 6.7x(약 +4%, 시나리오 6개 일관)로
  S2 예산(+5% 이내)을 통과했습니다. 트라이오드 경로에 더해진 비용은
  샘플당 add 2회 + mul 1회 수준입니다.

### 8.8 S1 구현 — 8x WDF 뉴턴 솔버 비용 절감 (2026-09-30)

구현 완료, 목표(8x ≤12%) 달성. 증거는 `docs/evidence/eon-vari-s1-20260930/`에
보존합니다. 계획 §8.2의 a항(tol 1e-6→1e-5)은 채택하지 않았습니다. tol 변화는
비트 동일(−311 dBFS)이라 비용에 기여하지 않았고, 대신 반복 경로 최적화로
목표를 달성했습니다.

설계:

- `KorenTriode.h`: softplus+logistic이 공유하는 exp 1회로 축약,
  `pow(e1, 0.4)` 재사용(비용 변화 없음, 널 −311 dBFS).
- `TriodeStage.cpp`: 뉴턴 루프를 `PlateSolve{vpk, ip}` 구조체로 재구성.
  평가-후-루프 + 최종 스텝 전 종료로 `koren.ip` 재사용(추가 전류 평가 1회
  제거). 허용오차 1e-6 유지.
- 선형 외삽 웜 스타트 `warm = 2·Vpk − VpkPrev`(`plateVpkPrev` 상태).
  평균 뉴턴 반복 2.80 → 2.19.

측정(48 kHz, 512 블록, 실시간 대비 %):

| 구성 | 이전 | 이후 |
|---|---|---|
| wdf-1x | 2.45 | 1.30 |
| wdf-2x | 5.19 | 3.45 |
| wdf-4x | 9.93 | 6.26 |
| wdf-8x | 19.04 | 11.88 |

- CTest 9/9, soundcraft 스모크 6/6. tone/alias 테이블은 출력 해상도(0.1 dB)에서
  이전과 동일.

한계와 결정 대기:

- 널 비교 peak −95.2 dBFS로 계획 기준(−100 dBFS)에 4.8 dB 미달. 원인은
  캐소드 피드백 루프의 혼돈적 fp 증폭입니다. 반복 경로를 조금만 바꿔도
  ~−95 dBFS로 수렴하고, tol 변화는 비트 동일이라 오차가 아닌 궤적 분기입니다.
  두 경로 모두 같은 방정식의 1e-6 스텝 기준 유효 해입니다. 스펙트럼/청감 지표는
  모두 동일하므로 수용 여부를 사용자에게 보고하고, 수용 시 §8.2의 널 기준을
  "peak −95 dBFS / rms −110 dBFS 이하"로 개정합니다.
- LUT 대안(§8.2 b)은 마이크로벤치에서 평가당 ~21% 절감, ip 오차 −147 dB였으나
  실구현 리스크 대비 이득이 작아 보류했습니다. 목표 달성으로 S3/S4 전제조건은
  충족됐습니다.

### 8.9 S3 — 출력 트랜스포머, 선형 근사

계획대로 선형 근사부터 넣고 스펙트럼을 측정했다. 스테이지는 튜브 스테이지
뒤, 오버샘플 도메인 안에 놓였다(오버샘플러당 인스턴스 하나). 효과가 세 가지다.
저역 셸프(+0.8 dB nominal, 150 Hz), 홀함수 비선형성(기울기 1, knee 1.5,
blend 0.15), 고역 셸프(-0.4 dB, 19 kHz).

측정(wdf-4x, drive 12, −12 dBFS, `Tools/sound_baseline.cpp`의 S3 표):

    40 Hz   rms +0.43 dB   H3 +3.0 dB   alias 변화 0.0
    1 kHz   rms -0.37 dB   H3 +3.2 dB   alias 변화 0.0
    15 kHz  rms -0.48 dB   H3 -6.2 dB   alias 절대값 -82.5 dBc

CPU 오버헤드는 1x +0.20 pp, 2x +0.27 pp, 4x +0.67 pp, 8x +0.65 pp다.
8x 총비용은 13.10%로 S1 목표(12% 이하)를 1.1 pp 넘지만, 비선형 인덕터가
아니라 셸프 두 개와 비선형성 한 번의 비용이다. 오버헤드가 8x에서도 거의
늘지 않는 점이 샘플당 고정 비용이라는 근거다.

게이트: CTest 9/9, soundcraft 6/6(`regressed: false`), auval PASS.
증거는 `docs/evidence/eon-vari-s3-20260930/`.

구현 중 바로잡은 세 가지가 이 단계의 실제 내용이었다. 첫째, Hz로 지정되는
셸프를 1차 one-pole로 만들면 −3 dB 지점이 샘플레이트에 따라 움직여 4x에서
15 kHz가 1.6 dB 죽었다(JUCE의 rate-correct 바이쿼드로 교체). 둘째, 스테이지
에 넣은 DC blocker가 40 Hz에서 0.64 dB를 먹어 저역 셸프를 상쇄했다(제거).
셋째, tanh의 H7이 4x 디시메이션에서 9 kHz로 폴딩되어 alias를 +28 dB
올렸고, 이를 `x/√(1+(x/k)²)`로 바꿔 H5를 −88 dBc까지 낮췄다(15 kHz
프로브 H3 델타가 +26.9 dB에서 −6.2 dB로).

결정 대기: 기본값은 Off. 레벨 매칭 블라인드 청취에서 이득이 확인되어야
비선형 히스테리시스 인덕터(WDF 루트 하나 추가, +50% 이상 CPU)로 넘어간다.
청취에서 이득이 없으면 선형 근사도 되돌린다.
